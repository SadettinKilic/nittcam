## D-010 Project JSON schema v1 interpretations (2026-11-16, T004)
Zod schema in `packages/core/src/schema/` (exported from `@nittcam/core`), modelled on spec §9.2. Where the spec is silent:
- **Strict objects:** unknown keys are rejected (no silent data loss); new fields arrive through a schema version + migration step.
- **Rect parts:** `params {w, h, r}` is the source; `outline` is optional and treated as a cache that is never read (`deriveOutline(part)` recomputes it). `r ≤ min(w, h) / 2`. The derived outline starts at `(r, 0)` (or `(0, 0)` when `r = 0`), runs CCW, uses quarter arcs with bulge `tan(22.5°)` and drops zero-length straight edges.
- **Contours:** `outline` and each `inners[]` entry are vertex arrays, implicitly closed. At least 3 vertices, or 2 when one segment is an arc (a circle). Direction (outer CCW, inner CW) is the stored convention but is not enforced by the schema; normalisation is T006's job.
- **Holes:** discriminated by `type`; every hole has an `id` (string, unique within its part, PO decision) so commands can address it. pocket = `id, d, cx, cy, depth, tool`; through = `id, d, cx, cy, tool` (no `depth`, it comes from stock thickness + machine sacrificial allowance, §4.5); groove = `id, d, cx, cy, depth, grooveWidth, tool`. For a groove, `d` is the **centreline** diameter (the tool centre follows that circle) and `grooveWidth < d` is required (PO decision). `tool` is the tool number in the machine profile (integer ≥ 1, PO confirmed). Rules that need other data (depth < thickness, d ≥ tool diameter, groove width vs tool) are validation rules for later tasks, not schema rules.
- **Enums:** `nesting.mode` ∈ `minWaste | fastest | minToolChanges` (§6.2); `cutting.leadIn` ∈ `arc | line`; `cutting.direction` ∈ `climb | conventional`; sheet `grain` ∈ `0 | 90` (free-angle grain is out of scope, §2.5); placement `rot` ∈ `0 | 90 | 180 | 270`.
- **Settings (§4.8, not in the §9.2 summary; PO decision):** top-level `settings.dimensionMode` ∈ `cut | finished`, default `cut` (a missing `settings` or `dimensionMode` parses as `cut`). In `finished` mode entered sizes are finished sizes and the edge-band thickness will be deducted from the cut size; only the field exists now, the deduction is implemented later.
- **Templates:** `params` is a record of number | string | boolean; `overrides` is the list of field names the user changed by hand.
- **Cross-references** checked by the schema: unique part ids; unique hole ids within a part; each placement points at an existing part, `index < qty`, and each copy is placed at most once. The grain rotation rule is enforced by the nesting engine, not the schema.
- **Migration:** `MIGRATIONS[n]` upgrades raw JSON from v`n` to v`n+1`; `parseProject(json)` upgrades then validates and returns `{ ok, project } | { ok: false, issues: [{ path, message }] }` (paths like `parts[0].holes[1].d`); `migrate(json)` throws `ProjectSchemaError`. Missing, non-integer or future `schemaVersion` is rejected with a clear message.
- **Dependencies:** `zod` 4.6.7 (MIT) in core, `fast-check` 4.10.2 (MIT) as a core devDependency.

## D-011 Command layer design (2026-11-16, T005)
Code in `packages/core/src/commands/` (registry, `plate/`, `part/`) and `packages/core/src/validate/`, exported from `@nittcam/core`. Spec §5.1, §5.4, §8.1.
- **Command = definition object:** `{ name, area, description, aiTool, params (Zod), check?, apply(draft, params) }`. `params` is the single source for runtime validation and the AI tool schema. Params objects are strict (unknown keys rejected).
- **Pure apply:** `applyCommand(project, name, params)` parses params, runs the optional precondition (`check`, e.g. duplicate part id), applies the recipe through Immer `produceWithPatches` and returns the new project plus forward and inverse patches. The input project is never mutated. The result is re-checked against `projectSchema`; a command that would produce an invalid project is rejected (`INVALID_RESULT`), so the stored project is always schema-valid. Rejections return `{ ok: false, error: { code, message, issues } }` and change nothing; codes: `UNKNOWN_COMMAND`, `INVALID_CONTEXT`, `INVALID_PARAMS`, `PRECONDITION_FAILED`, `INVALID_RESULT`.
- **Immer:** `immer` 11.2.9 (MIT, pinned; 11.2.10 was under two weeks old, D-008 rule). Core uses a private `new Immer({ autoFreeze: true })` instance so it never changes the global Immer config; `enablePatches()` is called once at module load. Projects returned by commands are frozen.
- **No clock in core:** the caller passes `{ actor: 'user' | 'ai', at }` with every command; `at` must be an ISO 8601 date-time with offset (validated by regex, not parsed). The log entry is `{ command, params, actor, at }` where `params` are the **parsed** params (defaults filled in), so replaying the log is deterministic.
- **CommandStack:** holds the current project, undo and redo stacks of `{ entry, patches, inversePatches }`, the append-only log and the current validation list. `execute` / `undo` / `redo` / `canUndo` / `canRedo`. Executing after an undo clears the redo stack. A rejected command touches nothing. Undo/redo are not log entries yet (open question; the `project_commands` table is T008+).
- **Ids are supplied by the caller** (`addPart.id`); core never generates random ids. `addPart` creates a rect part, appends it to `parts`, defaults: `name ''`, `qty 1`, `grainLock false`, zero edge band; inners/holes/templates empty. `addPart` params mirror the part JSON (`params: { w, h, r }`) so the `r ≤ min(w,h)/2` refine is reused.
- **Validation (rules, not schema):** `validateProject(project)` returns `{ code, severity, path, message }[]` and runs after every execute, undo and redo. The schema stays permissive (D-010). Rules now:
  - `PART_LARGER_THAN_SHEET` (error): rect part fits the raw sheet neither as is nor, when `grainLock` is false, turned 90°. Margin/gap are nesting concerns and not counted. Freeform parts are skipped until the arc-aware bbox (T006).
  - `HOLE_DEPTH_NOT_BELOW_THICKNESS` (error): pocket **and groove** depth must be `< stock.thickness` (§4.5). The "too close" warning needs a threshold the spec does not give (open question).
  - Hole diameter / groove width vs tool diameter (§4.5) is **not implemented**: the project has no tool table yet; it comes with the machine profile (T010).
- **AI tools:** `commandToolDefinitions()` returns `{ name, description, inputSchema }` for every command with `aiTool: true`, using `z.toJSONSchema(params, { io: 'input' })` (fields with defaults are optional). Refinements are not in the JSON Schema; `applyCommand` enforces them. Export and machine-profile editing are never AI tools (§5.4); `setMachine` only selects a profile and is allowed.

## D-012 Geometry core: bulge polyline (2026-11-16, T006)
Code in `packages/core/src/geometry/` (`constants`, `types`, `segment`, `polyline`, `transform`), exported from `@nittcam/core`. Spec §6.1, §4.4.
- **One vertex model:** `Vertex` is the schema type (`{x, y, bulge}`, D-010). `Polyline = { vertices, closed }`; `contour(vs)` wraps a stored (implicitly closed) contour. Segment i runs from vertex i to i+1; bulge = tan(θ/4), θ signed sweep, + = CCW. In an open polyline the last bulge is ignored.
- **Tolerances:** `EPS = 0.001` mm and `JOIN_TOL = 0.05` mm in `geometry/constants.ts`. One more constant, `MIN_BULGE = 1e-9`: smaller bulges are lines (sagitta < 5 nm on a 10 m chord; avoids a huge, imprecise circle). A zero-length chord is always a line. Core had no other magic tolerances to replace.
- **Segment helpers:** `arcOf` (centre, radius, start angle, sweep), `segmentMidpoint` (via the sagitta, no trig), `segmentLength`, `segmentArea`, `segmentBBox`, `sampleSegment`, `bulgeToSweep`/`sweepToBulge`.
- **Area:** exact for arcs: shoelace over chords plus r²(θ − sin θ)/2 per arc (series for |θ| < 0.01 to avoid cancellation). An open polyline is measured as if closed by a straight chord.
- **Orientation:** `'ccw' | 'cw' | 'none'`; |area| ≤ EPS² mm² is `'none'`. `normalize(poly, 'outer' | 'inner')` gives CCW/CW; open and degenerate polylines are returned unchanged (a copy).
- **Reverse:** a closed polyline keeps its start vertex (v0, vn−1, …, v1); each segment's bulge is negated and moved to the segment's new start vertex. For open polylines the ignored last bulge is carried along so reversing twice is the identity. Negation uses `0 − v` so no `−0` appears in output.
- **bbox:** endpoints plus the arc's axis extremes (0°, 90°, 180°, 270°) inside its sweep. Throws `RangeError` on an empty polyline.
- **Transforms:** `translate`, `rotate(poly, 0|90|180|270)` about the origin by swapping/negating coordinates (exact, no sin/cos), `mirror(poly, 'x' | 'y')` where `'x'` negates x (left-right flip) and `'y'` negates y. Mirroring negates bulges and flips orientation; it does not re-normalise (call `normalize`). `transform(poly, { mirror?, rotate?, dx?, dy? })` applies mirror → rotate → translate.
- **Closing (§4.4):** `isClosed` = flagged closed, or open with ≥ 3 vertices and ends within JOIN_TOL. `close` drops the duplicate end vertex (the previous segment now ends at the first vertex, bulge kept) and sets `closed: true`; a larger gap returns the open copy unchanged so the caller can warn "kesilemez, kapalı değil".
- **Wiring:** `PART_LARGER_THAN_SHEET` now covers freeform parts with the arc-aware bbox of `outline` (path `parts[i].outline`) and compares sizes with EPS slack (a bbox from arcs can overshoot an exact fit by rounding; rect parts get the same slack). Message sizes are rounded to 3 decimals. Margin/gap stay out (T012). `rectOutline` treats `r < EPS` as sharp corners (not machinable) and uses `sweepToBulge` for `QUARTER_ARC_BULGE`.
- **Tests:** unit tests per helper and fast-check properties on rectangles, rounded rectangles and convex polygons with bulges in [−0.15, 0.4] (inward arcs limited so they cannot cross at a ≥ 36° corner).

## D-013 Offset: our own TypeScript implementation (T007, PO decision, 2026-11-16)
Evidence: `docs/spikes/T007-offset.md`. Chosen: **C, our own arc-preserving offset in `packages/core/src/geometry/offset.ts`**.
- Why: as accurate as CavalierContours on every fixture and on 9 987 random contours (max deviation 2e-13 mm on fixtures); arcs stay bulges, so G2/G3 come out directly; 3.6 kB gzip, no runtime dependency, no second language (§8.4); does not inherit the 4 defects found in `cavalier-contours-js`. Clipper2 rejected: arcs come back only approximately (deviation above EPS) and its main repo is archived. Building Rust CavalierContours to WASM ourselves was rejected because it adds a second toolchain.
- `cavalier-contours-js` stays as a **devDependency test oracle only** (never in the bundle).
- API: in core, `offset(poly, d)` with d > 0 = right of travel. With stored orientations (outer CCW, inner CW), `+toolRadius` gives the tool-centre path for both. The toolpath layer (T014) exposes outer/inner semantics.
- `ARC_COLLAPSED` (corner radius < tool radius): a warning, surfaced to the user as a validation warning (§4.4) by the toolpath layer.
- `SPLIT` on an inward offset of an **inner contour or hole** is an **error that blocks export** (the tool cannot pass the neck, so the part stays attached). Implemented in the toolpath layer (T014). Safety first (§7).
- Known limits: single closed non-self-intersecting contour, no islands, worst case O(n²) (2000 segments ≈ 130–320 ms).
- Revisit triggers: pocket/island offsets, DXF contours with 1000+ segments, or a defect in C we cannot fix quickly.

## D-017 Security fixes are exempt from the two-week rule (2026-11-17, SEC, PO decision)
A dependency upgrade that fixes a published security advisory may use a release younger than two weeks (exception to D-008). Take the **lowest patched release on the same major**, prefer an older patched release over the newest one, never jump majors, and still pass the D-009 licence check. First use: **GHSA-mfr8-8qww-v76h** (CVE-2026-119790, moderate; `next` >=16.3.0 <=16.4.4, information disclosure across root params when a `'use cache'` function is called through `unstable_cache()`; `next build` aborted with `SecurityFatalError`). `next` and `@next/eslint-plugin-next` **16.4.3 → 16.4.5** (16.4.5 is the first patched release, published 2026-11-03; 16.4.6 not taken). Remaining moderate dev-only advisories without an in-range fix: esbuild GHSA-67mh-4wv8-2f99 (via `drizzle-kit` → `@esbuild-kit/core-utils`, pinned to esbuild 0.18) and minimatch GHSA-g3hv-75wg-m249 (via `typescript-eslint` 8.72, requires `minimatch ^10`, fix only in 11.0.1); revisit when those upstreams update.

## D-018 Cut list: parser, part commands, parts page (2026-11-17, T011)
Code in `packages/core/src/cutlist/` (`parseCutList`, `cutListToParts`), `packages/core/src/commands/part/` and `apps/web/app/projeler/yeni/parcalar/`. Spec §4.1, §4.8, §5.1, §5.4, §3.6.
- **Commands (all AI tools, part area):** `importCutList { parts: addPart-like rows[] }` adds 1–2 000 rect parts in **one undo step**; ids come from the caller and must be unique and free. `updatePart { id, name?, qty?, grainLock?, params?: {w?,h?,r?}, edgeBand?: partial }` needs at least one field; size changes are allowed on rect parts only (freeform → `PRECONDITION_FAILED`) and drop the cached `outline` (D-010: params are the source); `r ≤ min(w,h)/2` is checked on the result (`INVALID_RESULT`). `removePart { id }` also removes the part's placements. `duplicatePart { id, newId, name? }` deep-copies the part (holes, band, templates) right after the original; the copy is not placed. Lowering `qty` or removing a part drops layout placements that no longer point at a copy (layout is derived data, §9.2), so the project stays schema-valid.
- **Parser (pure):** quote-aware RFC 4180 splitting (quoted cells may hold delimiters, `""` and line breaks). **Delimiter:** first of tab → `;` → `,` that splits ≥ 80 % of the rows into the same column count > 1, else the first that splits half of them, else none (one cell per row, warning). An unquoted `;` or tab inside a comma-CSV cell can still win on a single row; the preview has a delimiter select. **Numbers:** the table's decimal separator is detected from cells like `396,5` / `396.5`; with a decimal comma (or no evidence) a dot is a thousands separator, with a decimal dot a comma is; `1.220.000`, `1.220,5`, `1,220.5` and space groups (`2 440`) are always unambiguous. Only `1.220`-style cells and no other evidence → read as **1220** (Turkish default) with the `THOUSANDS_ASSUMED` warning; both separators used as decimals → `MIXED_DECIMALS`. **Header:** first row is a header when ≥ 2 cells are known names, or 1 is and no cell is a number. Names (Turkish letters folded, `(mm)` / `[cm]` stripped): ad/adı/isim/parça/parça adı/name/part/açıklama · en/genişlik/width/w · boy/yükseklik/height/length/uzunluk/h/l · adet/miktar/qty/quantity/sayı/pcs · damar/damar yönü/grain · bant/kenar bandı/edge/edge band. Unknown columns → `ignore`; a field mapped twice keeps the first. **No header:** column kinds by content (≥ 80 % numbers = numeric); first text column = name, numeric columns in order = w, h, then qty if all integers; a column of only yes/no words = grain; confidence `high` only for the shape (name?, w, h, qty?) with nothing left over. Options override delimiter, decimal, header and mapping (the preview dropdowns).
- **Cell rules:** w/h required, number > 0. Qty empty or no column → 1; else an integer ≥ 1. Grain words: evet/e/var/x/✓/1/yes/y/true/kilitli vs hayır/h/yok/0/no/n/false/-/empty. Edge band: one thickness in mm for **all four edges** (empty/0/yok/- = none). Error codes `MISSING_COLUMN, REQUIRED, INVALID_NUMBER, NOT_POSITIVE, INVALID_QTY, INVALID_GRAIN, INVALID_EDGE_BAND` with column + field; English messages in core, Turkish in `tr.json` by code.
- **Unit:** never converted by the parser. `unitAmbiguous` when a w/h header says cm, or there is no unit in the header and **every** size is < 100. The UI then asks mm or cm and "Uygula" waits for the answer; cm multiplies w/h by 10 (rounded to 1 µm, so 39,6 → 396). Edge band thickness stays mm. A `(mm)` header is never ambiguous.
- **Confirmation:** the preview applies nothing; "Uygula" adds the **valid rows** and skips the invalid ones (the summary says how many are skipped). Corner radius from a paste is 0.
- **Parts page `/projeler/yeni/parcalar`** (menu "Oluştur") until the wizard (T023): an in-memory draft project (placeholder machine `draft`, 2800 × 2070 × 18 MDF), a `CommandStack` in the client, nothing saved. Grid cells keep typed text locally and run `updatePart` on Enter/blur (one undo step per edit; Enter moves down, Esc reverts; invalid input shows a Turkish error and runs nothing). "+ Satır ekle" adds a 100 × 100 part named "Parça n". Undo/redo buttons plus Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) outside text fields. Part ids: `crypto.randomUUID()` with a time+counter fallback (non-secure contexts). Validation issues of a part (e.g. larger than the sheet) are shown under its name.
