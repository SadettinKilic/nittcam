# UI conventions (spec §3, §3.7, §8.2, D-032)

Look: modern, calm, corporate (Linear / Vercel class). Neutral graphite surfaces, **one** accent (cobalt `accent`), Inter, generous spacing, 1 px subtle borders, soft shadows only on floating layers, short eased motion.

## Brand (T194, T194b, review #1 §4.1)
- **Shell logo = text wordmark (T194b, owner 2026-11-18):** `Wordmark` from `@nittcam/ui` renders "NittCAM" in Inter 800, tracking -0.04em, a subtle italic skew (`-skew-x-8`), "CAM" in `accent-text` (`tone="mono"` = one colour on accent). `variant="short"` = "NC" for the collapsed rail and top bars under 400 px. The sidebar header and the < 768 px top bar use it; the toolpath mark below stays for favicon/app icons and documents.
- Mark = the letter "N" drawn as one toolpath (lead-in arc, two legs, one diagonal pass, tool dot). Wordmark "NittCam": Inter 600, tight tracking, "Cam" in `accent-text`. Geometry lives once in `packages/ui/src/brand.ts`; `Logo` (`full` / `mark`, sizes 20/24/32, tone `tile` / `plain` / `mono`) and `LogoMark` render it as inline SVG with token classes.
- Where: the wordmark in the sidebar top-left (links to Ana sayfa, accessible name "NittCam, ana sayfa"), "NC" on the collapsed rail; the mark in favicon/app icons. Nowhere else in the app chrome; never inside canvases, buttons or toasts. The company / operator row lives at the bottom of the sidebar.
- Never recolour the logo outside tokens (`tile` on surfaces, `mono` with `text-accent-fg` on accent, `plain` in documents); never stretch, outline, shadow or rotate it; keep clear space of half the mark height around it.
- Static assets (`app/icon.svg`, `app/icon1.png`, `app/apple-icon.png`, `public/brand/*`) are generated by `node tools/brand/gen-icons.mjs` from the same geometry; regenerate them when the mark changes. Page titles are "<Sayfa> · NittCam".

## Stack
- Next.js App Router + Tailwind v4. Components are ours, in `packages/ui` (shadcn style on Radix via the `radix-ui` package), `cva` variants, `cn()` for class merging, `lucide-react` icons, `sonner` toasts, `cmdk` palette, `next-themes`.
- New or changed screens use `@nittcam/ui` components and tokens only. No ad-hoc buttons/inputs in apps/web and no local button class strings: use `Button` / `IconButton` / `buttonVariants` (the old `buttonClass` helper and the legacy token aliases `sidebar`, `ok`, `warn`, `*-bg` were removed in B4).
- **No native `<select>` or `<input type="checkbox">` in apps/web.** Use `Select` (`SelectTrigger` + `SelectValue` + `SelectContent` + `SelectItem`; `SelectGroup`/`SelectLabel` for groups) and `Checkbox` from `@nittcam/ui`. Put `id` and `data-testid` on the trigger, link the label with `htmlFor`, mirror the value as `data-value` on the trigger for tests, and use a sentinel such as `__none__` instead of an empty item value (Radix forbids `""`). In e2e use `pickOption()` / `optionLabels()` from `e2e/tests/wizard-helpers.ts` instead of `selectOption`; `check()` and `toBeChecked()` work on `Checkbox`.
- Gallery of every component/variant/state: `/dev/ui` (dev only). Add a new component there in the same PR.

## Tokens (`packages/ui/src/tokens.css`, the only place for values)
- The Tailwind default palette is **off** (`bg-blue-500` does nothing). No hex/rgb in components or screens.
- Use **semantic roles**, not raw scales (`neutral-*`, `brand-*`, `success-*`... exist only for the token file and data-viz):
  - Backgrounds: `bg` (page), `surface` (cards, panels, inputs), `surface-subtle` (sidebar, wells, table headers), `surface-raised` (popover, menu, dialog), `surface-hover`, `surface-active`, `overlay` (modal scrim).
  - Borders: `border-subtle` (dividers inside cards), `border` (default), `border-strong` (inputs, hover).
  - Text: `fg`, `fg-muted` (secondary), `fg-subtle` (hints, placeholders), `fg-disabled`.
  - Accent: `accent` (solid fill) + `accent-fg` (text on it), `accent-hover`, `accent-text` (links, active nav text), `accent-subtle` (selected row/tint), `accent-border`; `focus` is the focus-ring colour.
  - Status `success | warning | danger | info`: `X` solid, `X-fg` text on solid, `X-text` coloured text on surfaces, `X-subtle` tint, `X-border`. `danger-hover` for destructive buttons.
  - Canvas tokens: `canvas` (well behind a drawing), `sheet`, `sheet-waste`, `sheet-margin`, `sheet-edge`, `grid`, `grain`, `part`, `part-stroke`, `part-locked`, `part-locked-stroke`, `selection`, `sim-*` (depth top/bottom, rapid, tool, table, envelope, zero, tab, part, part-stroke, badge, badge-fg). All have dark values.
  - Konva/3D cannot use classes: read the tokens with `readTokenColors(TOKENS, getComputedStyle(document.documentElement))` and subscribe with `onThemeChange(cb)` (both in `apps/web/lib/canvas-theme.ts`; it watches the `<html>` class and the system scheme, returns the unsubscribe) so the canvas recolours live on a theme switch, without a reload. Never hard-code canvas colours.
- Radius: `rounded-sm` (6 px: badges, kbd), `rounded-md` (8 px: buttons, inputs), `rounded-lg` (10 px: menus, popovers), `rounded-xl` (14 px: cards, dialogs).
- Spacing: 4 px grid (`p-1` = 4 px). Control heights: `h-control-sm` 32 px, `h-control-md` 40 px (default; ≥ 40 px touch target, spec §3.7), `h-control-lg` 48 px.
- Elevation: `shadow-xs` (buttons, inputs), `shadow-sm` (cards), `shadow-md` (popover, menu), `shadow-lg` (dialog, sheet), `shadow-xl` (command palette). Flat surfaces use a border, not a shadow.
- Type (T195): Inter (`--font-inter`, UI) + JetBrains Mono (`--font-jetbrains-mono` → `font-mono`), both self-hosted by `next/font` (OFL, latin-ext for İ ı Ş ğ); no Consolas/Courier fallback. Scale `text-2xs` 11 · `xs` 12 · `sm` 14 (UI default) · `base` 16 · `lg` 18 · `xl` 20 · `2xl` 24 · `3xl` 30 · `4xl` 36; headings `font-semibold`, large sizes carry negative tracking.
- Page titles: `text-xl sm:text-2xl` (20 px phone, 24 px desktop) via `PageHeader`. KPI numbers `text-3xl` + `numeric`, unit in `fg-muted`. The wizard H1 is the stepper title (step name written once).
- **Numbers are the signature:** every measurement uses `Measure` from `@nittcam/ui` (value(s) + unit, Turkish digits, tabular, unit muted; `mono` for coordinates/read-outs; `[w, h]` joins with ×). Inside a translated sentence use `fillRich()` (`apps/web/lib/fill-rich.ts`) with a `{size}` placeholder instead of hand-formatting "{w} × {h} mm".
- `font-mono` for G-code, file names, hashes, coordinate read-outs; canvas labels use `canvasMonoFont()` from `apps/web/lib/canvas-theme.ts` (Konva cannot read classes).
- Density: comfortable is the default (40 px controls/rows, 16 px panel padding). A container may opt in with `data-density="compact"` (32 px controls, 36 px rows `h-row`, 12 px `p-panel`) for dense tools (drawing-board inspector, long lists). Not a user setting until T183.
- Motion: `--duration-instant|fast|base|slow` (80/120/180/280 ms), `ease-out`; animations `animate-fade-in|out`, `animate-pop-in|out`, `animate-sheet-in|out-right|left`. Use `duration-(--duration-fast)` in transitions. The global reduced-motion rule turns all of it off.
- Contrast: every text/background pair is AA in both themes; `packages/ui/src/tokens.test.ts` enforces it. A new pair → add it there.

## Theme
- `ThemeProvider` (in the root layout) = next-themes, class strategy on `<html>`, `system` default, stored under `nittcam-theme`, no flash. Read/set with `useTheme()`; `ThemeSwitcher` gives the Sistem/Açık/Koyu control.
- Style dark mode through tokens, not `dark:` overrides. `dark:` is only for rare exceptions.

## Components and states
- Every interactive element is keyboard operable with the visible focus ring (`focus-visible:` 2 px `focus` ring with offset). Icon-only buttons need `aria-label` (IconButton enforces it).
- Numbers: `NumberInput` parses Turkish input (`12,5`, `1.200,5`), shows the unit suffix (mm) and errors; display with Turkish formatting (1.220 × 2.440 mm).
- Every screen needs empty, loading (`Skeleton`) and error states. Forms use `FormField` (label + hint + error, wired with aria-describedby).

## Text
- All UI text in translation files (`apps/web/messages/tr.json` first). Components in `packages/ui` take text as props; they never hard-code Turkish strings.
- Plain workshop language ("İçini boşalt", "Sadece çember (kanal)"), never CAM jargon without explanation.

## Behaviour
- **Simple mode** for old computers: no 3D, no heavy animation.
- **Reduced motion:** honour `prefers-reduced-motion`; pause animations when the tab is hidden.
- Responsive: 390 / 768 / 1024 / 1440 px, no page-level horizontal scroll.
- Heavy work (nesting, toolpath) runs in a Web Worker; the UI never freezes.
- The UI never mutates the project directly; it always calls commands (command-layer skill).
- Menu (T194a): live items Ana sayfa, Makineler, Projeler, Oluştur (kept until FQ4 is answered) and a prominent "+ Yeni proje" at the top; items not built yet (Şablonlar, Ayarlar) in a muted "Yakında" group at the bottom, never between live items. One accent-filled "Yeni proje" per screen (the sidebar one; pages repeat it only below 768 px). Domain icons (`RouterIcon`, `SheetIcon`, `GrainIcon`, `NestingIcon`, `ToolpathIcon`, `AirCutIcon` from `@nittcam/ui`, lucide-compatible) for CNC concepts; never the chip/drill icon for a machine. UI text says "dışa aktarma", not "export".
- Visual QA: `pnpm e2e:visual` (Playwright `visual` project, 1440×900 and 390×844, light + dark, `snap()` and `expectNoA11yViolations()` from `e2e/tests/visual/helpers.ts`).

## App shell (B2, T103–T105)
- Every page renders inside `AppShell` (`apps/web/components/shell/`): sidebar (224 px, collapsible, state remembered), sticky top bar (breadcrumb + title), drawer below 768 px, skip link. Pages render their own `<main>` inside `#content`.
- Top-bar slots from a page: `<ShellActions>` (page actions), `<ShellStatus>` (save status, e.g. the wizard autosave) and `useShellTitle(title)` (last breadcrumb, e.g. the project name) from `shell-context.tsx`.
- Shortcuts live in one registry, `apps/web/lib/shortcuts.ts`; it drives the global handler, the Ctrl/⌘+K palette hints, tooltips, the `?` dialog and `aria-keyshortcuts`. Shortcuts never fire while typing in inputs.
- Feedback: `notify.success|info|error` (sonner) for toasts; `EmptyState` / `ErrorState` (with `onRetry`) for empty and failed lists; `PageSkeleton` or `Skeleton` while loading; `CanvasBoundary` around Konva/3D canvases so a canvas crash keeps the page.
- `/dev/ui` renders without the shell, so gallery baselines do not move with shell changes.

## Page patterns (B3, T106–T108)
- Page body: `pageContainer` + `PageHeader` (title, description, actions on the title's baseline; actions drop below on phones) and `SectionHeader` (section title with a right-aligned link on the same line) from `apps/web/components/page/page-header.tsx`. Use `sectionLink` for "Tüm … →" links and `focusRing` for custom focusable elements.
- Data lists: TanStack Table v9 (`useTable`, `tableFeatures`, `createColumnHelper`) inside a `Card` on wide screens; a card list below `lg`. Keep the same accessible names on both (e.g. `Düzenle: <name>`).
- Long forms: sections as `Card`s with title + one-line hint, a sticky side index on `lg`, a floating sticky save bar (status left: clean / unsaved / errors / saving; actions right), and a leave guard (in-app links, reload, Vazgeç) when dirty. Every mm/feed/rpm value uses `NumberInput` with a unit; parse errors block saving and show inline.
- Wizard step panels: `Panel` (titled card section), `Callout` (warning/danger/info/success notice with an icon), `panelClass` and `canvasWellClass` (background well behind a canvas) from `apps/web/components/wizard/panels.tsx`; reuse them instead of new border/background strings.
- Tab strips that can grow (plates, sheets) scroll horizontally in an `overflow-x-auto` wrapper (`TabsList` with `w-max flex-nowrap`, triggers `shrink-0`); the toolbar next to them stacks below on phones instead of wrapping into the tabs.
- Verification badges: `MachineStateBadge` (`STATE_TONE` in `lib/machine-state.ts`); steppers use `stepStatuses()` (done / current / upcoming, `aria-current="step"`).
- Scrollable regions (`overflow-x-auto` around tables without inputs) need `role="region"`, an `aria-label` and `tabIndex={0}` (axe `scrollable-region-focusable`).
- Visual QA for redesigned pages: full-page `expectNoA11yViolations(page)` in light and dark at 1440 and 390 px. Captures of pages whose data is shared with other tests use `snap(page, name, { baseline: false })` (review capture only); deterministic states (fresh visual DB) get baselines.
