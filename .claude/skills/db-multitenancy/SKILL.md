# DB & multi-tenancy (spec §8.6, §9)

- PostgreSQL + Drizzle ORM. Schema and migrations in `packages/db`. Project JSON is stored in a `jsonb` column.
- **Every table has `company_id`; every query filters by the session's company.** Enforce it through a tenant-scoped query helper, never ad hoc. There is a test proving that company A cannot read company B's data, for every table.
- **Roles are checked on the server** (admin / operator); hiding things in the UI is not enough.
- **Revision lock (optimistic):** each save increments `revision`; a write with an old revision is rejected (409). Locally only the unsent command queue is kept.
- **Immutable versions:** machine profile edits create a new `machine_profile_versions` row; exports and validations always reference a specific version.
- Migrations: forward-only, reviewed, generated by drizzle-kit, and they run in CI against a fresh DB.
- Project JSON carries `schemaVersion`; old projects open through migration functions in `packages/core/schema`.
- Secrets only in environment variables. Never read or commit `.env`.
- Uploads (DXF, Excel, photos): size and type limits.
- Tables: companies, users, machines, machine_profile_versions, tools, materials, templates/template_versions, projects, project_commands, exports, validations, offcuts, chat_messages, ai_usage.
